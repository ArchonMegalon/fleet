# LTD Cadence and Followthrough System

## Purpose

This file defines how the LTD stack should create recurring user value rather than one-off capability demos.

## Product rule

LTDs should amplify Chummer's cadence.
They should help recruit, remind, publish, measure, schedule, and follow through on product truth that Chummer already owns.

## First recurring loops

The first recurring loops should be:

* weekly world dispatch
* open-run recruitment and reminder packets
* beginner clinic and GM office-hour followthrough
* creator publication and update followthrough
* blocker-reactivation or recovery followthrough

## Tool fit

The stack should be used as follows:

* `ProductLift`, `Deftform`, `Icanpreneur` for pain and demand capture
* `Signitic` and `Emailit` for recurring outward-facing followthrough
* `vidBoard`, `Taja`, `MarkupGo`, `PeekShot`, and related render tools for visible proof and recap
* `Lunacal`, `FacePop`, `Teable`, `NextStep`, and approval tools for human and operator followthrough

## Boundary rule

The LTD stack should create cadence, not shadow authority.
If a loop cannot be mirrored back into Chummer-owned receipts, it should stay outside the canonical product lane.
